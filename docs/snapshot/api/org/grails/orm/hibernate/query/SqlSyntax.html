Package: org.grails.orm.hibernate.query

[Java] Enum SqlSyntax

      • org.grails.orm.hibernate.query.SqlSyntax 
      • public enum SqlSyntax
extends java.lang.Enum

        How a query text is read: what, besides string literals in single quotes, identifiers in double quotes or backquotes and block comments, it may hold. The syntax of native SQL is the database's, resolved from its Hibernate dialect the way RegexDialectPattern resolves the regular expression operator, so that every reader of native SQL in this package reads it as the database will. The databases differ in what a character means:

        • square brackets quote an identifier on SQL Server and Sybase, and subscript an array elsewhere;
        • a backslash escapes in a MySQL or MariaDB string, and in a PostgreSQL E'...' string only;
        • $tag$...$tag$ is a string on PostgreSQL, $$...$$ on H2, and q'[...]' on Oracle;
        • # starts a comment on MySQL, which also needs a space or a control character after --;
        • block comments nest on PostgreSQL and SQL Server, and not elsewhere;
        • {@code //} starts a comment on H2, and an alias may be written as a string on MySQL and SQL Server.
        The defaults of each server are assumed. The modes that change the lexical rules, such as NO_BACKSLASH_ESCAPES and ANSI_QUOTES of MySQL, are not read from the server. HQL has block comments only: Hibernate's parser rejects -- and {@code //}, so b.height--1 is a subtraction there.
        Since:
        8.0.1
