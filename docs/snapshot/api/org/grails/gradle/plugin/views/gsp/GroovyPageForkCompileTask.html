Package: org.grails.gradle.plugin.views.gsp

[Groovy] Class GroovyPageForkCompileTask

      • org.grails.gradle.plugin.views.gsp.GroovyPageForkCompileTask 
      • @CompileStatic
@org.gradle.api.tasks.CacheableTask
abstract class GroovyPageForkCompileTask
extends AbstractCompile

        Abstract Gradle task for compiling templates, using GroovyPageForkedCompiler This Task is a Forked Java Task that is configurable with fork options provided by ViewCompileOptions

        Cacheable. What a page compiles to depends on the Groovy that compiles it, the Java it is compiled for and the classes it is compiled against, and each of them is part of the key. The compiler runs from getClasspath(), which AbstractCompile declares a classpath input, fingerprinted by content, so a build that resolves another Groovy is not handed this one's pages; getJavaLauncher() and the target compatibility say which Java. The Grails environment whose configuration the pages are compiled with, getGrailsEnvironment(), is part of the key too. The pages are fingerprinted by their path under the source, so a checkout in another directory reuses what this one compiled.

        Compiles every page, from an empty destination, each time it runs; see ViewCompileDestination. The compiler's own economy, of leaving a page alone whose class is newer than its source, would otherwise carry pages of another environment, classpath or configuration, or pages that no longer exist, into the archive and the build cache.

          • @org.gradle.api.tasks.Internal
            final org.gradle.api.provider.Property<java.lang.String> grailsEnvironment

            The Grails environment the pages are compiled for, by name.

            A page is compiled against the configuration of one environment: the forked compiler merges that environment's block of application.yml and application.groovy over the rest before it reads the codecs and the other settings a page carries once compiled. The environment is therefore part of what the pages are, and part of the cache key, so pages compiled for one environment are not restored into a build for another.

            Defaults as ViewCompileEnvironment.defaultFor says: to an environment the fork options of getCompileOptions() already name, else to the one the build runs with, else to development. Read as getStatedEnvironment(), which is the input.

Internal rather than an input directory: its pages are fingerprinted as part of getSource(), and it need not exist - a project whose only pages are generated, a plugin that scaffolds controllers and has no views of its own, has none, and an input directory that does not exist fails validation.           • @org.gradle.api.tasks.Nested
            abstract org.gradle.api.provider.Property<org.gradle.jvm.toolchain.JavaLauncher> getJavaLauncher()

            The Java runtime the pages are compiled by.

            Compilation is forked, and a forked process runs whatever JVM it is given rather than the one the project asked for. Left to itself it inherits the JVM running Gradle, so a project declaring a toolchain gets its pages compiled by a different Java than everything else it builds -- which shows up as an UnsupportedClassVersionError at the moment a page is first rendered, long after the build called itself successful.

            Nested rather than internal because the Java that did the compiling is part of what the result is: pages built by one are not left standing when the build asks for another.
