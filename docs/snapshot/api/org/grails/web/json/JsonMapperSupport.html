Package: org.grails.web.json

[Java] Class JsonMapperSupport

    • org.grails.web.json.JsonMapperSupport 
    • public final class JsonMapperSupport
extends java.lang.Object

      The Jackson tools.jackson.databind.json.JsonMapper that grails.converters.JSON writes through. With grails.converters.json.legacy, the default, it is DEFAULT, which writes the JSON token stream as Grails 8 wrote it, while the converter's marshallers write every value, whatever the spring.jackson.* settings say. With the setting false it is a copy of the application's mapper with the converter's modules, so that spring.jackson.* settings apply, or of a default mapper where the application has none.

      Without the legacy setting, the mapper writes the JSON token stream, and the values the converter hands it: every value that it has a dedicated serializer for, such as dates and times, Month, UUID, Locale, byte[], types with a @JsonValue and the types that Jackson modules registered with the application serialize, and, rendering as Spring Boot does, beans, records, collections, maps, arrays and Optional values, whose nested values the converter renders as any other value. The JSON text is written through HtmlSafeJsonWriter.

      JSON is written with a copy of the mapper whose serializers offer the values nested in a value they write, such as a property that a module's serializer writes, to the nested value writer the value is written with (writeValue(JsonGenerator, Object, Predicate)), so that Grails marshallers render those values as well.

      Since:
      9.0

        • public java.lang.Object parse(java.lang.String text)

          Parses JSON text with the mapper's own parser, so that the parser features the mapper is configured with decide what is accepted, such as comments or single quotes. Objects and arrays become the JSONObjects and JSONArrays that grails.converters.JSON#parse has always returned, with the number types Grails' own parser gives: an Integer, a Long or a BigInteger for a number written with as many digits after the decimal point as its exponent moves, such as 15 or 1.5e1; a Double for any other number written with the digits Double.toString writes for it, such as 2.5; and otherwise a BigDecimal, such as 1.00, 1e3 or 1e400. NaN and Infinity, which a mapper may accept, are Doubles.

          Text after the value is rejected, as the mapper rejects it when it reads a value, unless the mapper disables DeserializationFeature.FAIL_ON_TRAILING_TOKENS.

          throws:
          JSONException if the text is not JSON the mapper's parser accepts
          Parameters:
          text - the JSON text
          Returns:
          the value: a JSONObject, a JSONArray, a String, a number, a Boolean or null
          Since:
          9.0

        • public boolean rendersValue(java.lang.Class<?> type)

          Whether the mapper writes values of the type itself, with a dedicated serializer for a single value. Beans, records, Optional and other reference types, collections, maps, iterables, streams and object arrays are left to Grails marshallers, so that the values they contain are rendered as any other value is. So is an enum the mapper writes with Jackson's enum serializer or by its @JsonValue, so that it renders by name. The mapper writes any other enum itself: one with a serializer of its own, such as Month, and, on the mapper grails.converters.JSON writes through without grails.converters.json.legacy, which writes enums by name, every enum.

          Parameters:
          type - a value type
          Returns:
          whether the mapper writes values of the type
