Package: org.apache.grails.datamapping.core.querytail

[Groovy] Class QueryTailRequestAttribution

    • org.apache.grails.datamapping.core.querytail.QueryTailRequestAttribution 
    • @CompileStatic
class QueryTailRequestAttribution
extends java.lang.Object

      Attributes a captured statement to the web request on the current thread. The framework that serves a request keeps it, and what it resolved it to, on the thread that serves it, so a statement run by an interceptor, the action or the view all land on the same page. The first statement of a request gives it an id that every later statement of that request repeats, which is how the query-tail command counts statements per request. Each capture file keeps its own request ids, so a request recorded to another file cannot consume or reuse one of its ids. Work on any other thread is attributed to the thread by name.

      What a request was resolved to is read by the readers on the class path, which are found with java.util.ServiceLoader, so that this class depends on no web framework: Grails URL mapping provides one, which gives a request the page of the controller and action Grails resolved it to and reads its path against the URL mapping it matched. The request is recorded as its method and path, with the values in the path replaced by ?: as the reader that resolved the request reads it, else, for a request a Spring MVC handler serves, as the pattern its handler mapping matched, whose variables are replaced. A request included in another, as <g:include> includes one, is recorded as the URI it was included by, rather than the path of the request that includes it. When the path cannot be read so, as for a statement of a filter that runs before the controller is chosen, for a request that never reaches one, or for a path that does not follow what matched it, no segment's role is known and every segment is replaced, so that an id, a token or a key carried in a path never reaches the capture file. A request is described once and its line reused for its later statements, until its path, the pattern it matched or what a reader resolved it to changes, as a forward or an include changes them.

      Work a request starts on another thread that carries the request with it, as Grails promises and @Async methods do, counts for the request. A statement that runs once the request has completed is attributed to its thread.

      An endpoint that runs whichever operation its client sends, as a GraphQL endpoint does, serves every operation on the one page; it names the operation it runs with beginOperation, and the statements the request runs until the operation ends are counted under the operation as well as under the page: graphql/index (query BookList).

      Spring Web is optional: without it on the classpath every statement is attributed to its thread.

        • static java.lang.Runnable beginOperation(java.lang.String operation)

          Counts the statements the request on the current thread runs, from now until the operation ends, under the operation as well as under the page of the request: the page of each is the page of the request with the operation after it, in parentheses, as graphql/index (query BookList), so that an endpoint that runs whichever operation its client sends, as a GraphQL endpoint does, shows each operation as a page of its own. A request no reader resolved is shown by its request line with the operation after it. An operation begun while another runs is the one the request runs until it ends, and the other runs on after it, whichever of them ends first.

          Parameters:
          operation - names what the request runs; it is recorded as it is given, so it names no value
          Returns:
          ends the operation, on whichever thread it ends, and does nothing once it has, or when there was no request on the thread to begin it in
