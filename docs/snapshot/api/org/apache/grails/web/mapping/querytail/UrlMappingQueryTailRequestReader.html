[Groovy] Class UrlMappingQueryTailRequestReader

    • org.apache.grails.web.mapping.querytail.UrlMappingQueryTailRequestReader
    • All Implemented Interfaces and Traits:
      QueryTailRequestReader
      @CompileStatic
class UrlMappingQueryTailRequestReader
extends java.lang.Object
implements QueryTailRequestReader

      Reads the controller and action Grails resolved a request to, for the query-tail capture, which finds it with java.util.ServiceLoader. The page of a request is its controller and action, with the namespace of the controller before them.

      The controller, action and namespace a request names count only when they are those of the controller class Grails resolved the request to: the class of the URL mapping it matched, else the one it keeps on the request. URL mapping sets the names of each mapping it reads, so the names of a mapping that resolved no controller are values of its path, which it reads as names, and the class Grails keeps on the request may have been looked up by such a name. An action counts only when that controller has it, and a namespace only when it is the one the controller is declared in. Grails names the default action only as it calls it, after the before interceptors have run, so a request to /book is on the page of the default action of the controller its mapping matched from its first statement.

      The path of a request is read against the URL mapping Grails matched: a segment the mapping spells out is kept, as is a variable segment that names the controller, action or namespace, and every other variable segment is replaced whole, including a segment a mapping such as /reset/${token}_confirm glues a value into, as is every segment a greedy token takes and every path parameter after a semicolon, such as a jsessionid the container rewrote the path with. A path the mapping does not spell, as one kept from before a forward, or a request whose mapping Grails has let go of, is not read: no segment's role is known, and only its shape is recorded.

      A request is resolved once, and resolved again only once one of the request attributes it was resolved from has changed, as naming the action Grails calls changes them.
