Package: org.apache.grails.testing.http.client.bench

[Groovy] Class AppHttpBench

    • org.apache.grails.testing.http.client.bench.AppHttpBench 
    • @CompileStatic
final class AppHttpBench
extends java.lang.Object

      App-level HTTP microbench helper that emits JMH-compatible JSON so results can be compared with :grails-test-examples-benchmarks:jmhCompare using the same methodology as the framework JMH suite.

      This type lives in test fixtures, not the published main API of grails-testing-support-http-client.

      Measurement model:

      • warm up the full Spring Boot stack with warmup requests (discarded)
      • collect samples timed requests as one raw series
      • split the series into chunks contiguous chunks and report a 95% t-interval over the chunk means, the way JMH reports one over its iteration means
      • also emit a CPU ruler entry that does the same work as the JMH CpuRulerBenchmark so the runner-health gates apply

      Enable gated specs with -PappBench=true. Optional properties: appBenchWarmup, appBenchSamples, appBenchChunks, appBenchOut, appBenchOutDir.

      • Property Detail

        • static final int DEFAULT_CHUNKS

          Default number of chunks. JMH's PR profile produces 10 iteration means (2 forks x 5 iterations), and scoreError needs about that many for the comparator's disjointness test to be able to fire: with 2 chunks the t critical value is 12.706 and the interval swallows any realistic delta.

        • static final java.lang.String RULER_BENCHMARK

        • static final int RULER_ROUNDS

          Rounds per ruler sample, the same as CpuRulerBenchmark.integerArithmetic.

        • static final int RULER_WARMUP

          Ruler calls discarded before sampling, independent of appBenchWarmup. The HTTP warm-up is sized for millisecond requests; a microsecond loop needs tens of thousands of calls before C2 has compiled it, and sampling earlier records the JIT transition as a runner-health deviation.
