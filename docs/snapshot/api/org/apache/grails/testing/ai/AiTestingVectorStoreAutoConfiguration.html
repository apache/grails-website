Package: org.apache.grails.testing.ai

[Groovy] Class AiTestingVectorStoreAutoConfiguration

    • org.apache.grails.testing.ai.AiTestingVectorStoreAutoConfiguration 
    • @CompileStatic
@AutoConfiguration(after=AiTestingAutoConfiguration)
@AutoConfigureOrder(value=Ordered.LOWEST_PRECEDENCE)
@ConditionalOnClass(value=SimpleVectorStore)
@ConditionalOnProperty(prefix=AiStubProperties.PREFIX, name="enabled", havingValue="true", matchIfMissing=true)
class AiTestingVectorStoreAutoConfiguration
extends java.lang.Object

      Registers an in-memory vector store over the stub embedding model when Spring AI's vector store module is on the classpath, no vector store is selected and the application defines none, so code that stores and searches documents can be tested without a database. The store is a ResettableSimpleVectorStore, which a test that shares a context clears between features.

      The guard on spring.ai.vectorstore.type matters because this auto-configuration would otherwise be evaluated before Spring AI's own: the stub would be registered first and a store the application selected, such as PgVector, would back off. It is also ordered after every other auto-configuration, so the embedding model it needs exists when its condition is evaluated whether the stub or a provider the application selected supplies it. Like the model stubs, the store is a fallback bean: one the application defines later, in resources.groovy or doWithSpring, wins.
