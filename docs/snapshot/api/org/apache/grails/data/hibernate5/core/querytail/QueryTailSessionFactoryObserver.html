Package: org.apache.grails.data.hibernate5.core.querytail

[Groovy] Class QueryTailSessionFactoryObserver

    • org.apache.grails.data.hibernate5.core.querytail.QueryTailSessionFactoryObserver
    • All Implemented Interfaces and Traits:
      org.hibernate.SessionFactoryObserver
      @CompileStatic
class QueryTailSessionFactoryObserver
extends java.lang.Object
implements org.hibernate.SessionFactoryObserver

      The session factory observer GORM installs on a session factory when query-tail capture is enabled. It wraps the connections the connection provider of the session factory hands out, so that each statement is recorded as it runs, once for each entry submitted in a batch, rather than when the reusable statement is prepared. The statement runs unchanged, and so does the statement inspector the application configured, if any: it sees the statement first, and the statement it returns is the one run and recorded.

      The session factory owns the capture. Each session factory a configuration builds has an observer, and a capture, of its own, so a configuration that builds several leaves each of them recording until it closes. Its QueryTailRecorder opens the capture when the session factory is created, and takes from the dialect, as QueryTailDialects tells it, how the database quotes values; it closes the capture as the session factory starts to close, so that the schema Hibernate drops as it closes, as create-drop has it, is no more recorded than the schema it created as it started, and a session factory that fails to start leaves no capture open either.

      The observer is added to the session factory as Hibernate builds it, through the factory the configuration hands Hibernate, next to the observers of the configuration, which it leaves as they are, wherever the application sets them; the connection provider is decorated in the service registry of the session factory, through the contributor the configuration hands Hibernate, whatever provider the registry the session factory is built with has.

      Nothing of this is installed unless QueryTailSettings.SETTING_ENABLED is set, so an application that does not capture pays nothing per statement.
