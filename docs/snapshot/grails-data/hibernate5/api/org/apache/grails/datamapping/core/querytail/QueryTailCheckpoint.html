Package: org.apache.grails.datamapping.core.querytail

[Groovy] Class QueryTailCheckpoint

    • org.apache.grails.datamapping.core.querytail.QueryTailCheckpoint
    • All Implemented Interfaces and Traits:
      Resource
      @groovy.transform.CompileStatic
final class QueryTailCheckpoint
extends java.lang.Object
implements Resource

      Lets a process that captures statements be checkpointed with CRaC, which refuses to checkpoint a process that holds a file open: before the checkpoint every QueryTailCapture file is closed, along with its lock file, and after the restore each is opened again, as a capture opening it first would open it.

      It is registered with the global context of org.crac as the first capture file opens, when org.crac is on the classpath, as checkpointing with Spring requires it to be. Spring stops its lifecycle beans before a checkpoint taken while the application runs, but none has started when the checkpoint is taken as the context refreshes, while the capture files open as the datastores are built, so the capture takes part on its own.
