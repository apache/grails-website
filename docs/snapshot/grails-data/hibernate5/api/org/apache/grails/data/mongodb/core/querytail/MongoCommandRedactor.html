Package: org.apache.grails.data.mongodb.core.querytail

[Groovy] Class MongoCommandRedactor

    • org.apache.grails.data.mongodb.core.querytail.MongoCommandRedactor 
    • @groovy.transform.CompileStatic
final class MongoCommandRedactor
extends java.lang.Object

      Takes the values out of a MongoDB command before it is captured. A command is a document, so there is nothing to parse: every value becomes QueryTailRedactor.PLACEHOLDER, and the keys, which are the options of the command, its operators and the field names of the collection, are kept, except where a key may be data. The keys of a document stored in a map property, or in a property or a collection the mapping does not know, are recorded as the placeholder too, and so is every segment of a dotted path past such a key. So is a key at the top of stored data, the documents an insert writes, a replacement document, the fields an update writes and the operand of a literal, unless the mapping knows it, as the name of a dynamic attribute may be data; the keys at the top of a condition, a pipeline, a sort or a projection are the fields the application asks for, and are kept. An update that is a pipeline writes the documents its stages build: the keys at the top of what a $set, $addFields or $project stage holds, of the new root of a $replaceWith or $replaceRoot, and of a document $mergeObjects merges into it are fields written, kept only when the mapping knows them, as those of a classic update are. A numeric key is kept only where it indexes an array the mapping knows; in a map, in an element of an array, which is a map or a document unless the field is a list of lists, or at the top of a document, it is data. A $ key is kept as an operator only where operators go, in a condition, a pipeline and the operators of an update, and in a condition only when it is one of MongoDB's query operators: any other, such as a key beside the geometry of $near, is recorded as the placeholder, and so is everything under it. The operand of $elemMatch is a condition wherever it is, in a projection as in a filter; in stored data, the documents an insert writes, a replacement document and the values an update operator writes, it is a field name, which MongoDB allows to start with $, and is recorded as the placeholder unless the mapping knows it. So is a $ key in the operand of a comparison in a condition, such as $eq or $in, or an implicit document or array equality, which holds the value the field is compared with, and in a DBRef, whose $ref, $id and $db a condition reads as fields compared with their whole value, in any order; in an aggregation expression, which $expr, the let of a command and the stages that compute fields hold, the operands of a comparison are expressions, and their operators are kept, except in the operand of a $literal or $const, which is stored data. The keys of the command itself are its options, and are kept, but a document under an option is read only where the option is known to hold one: the fields, a condition, a pipeline, an update or stored data, or options in turn, as the concerns, the collation and the cursor of a command, the statements of a write, the indexes it builds and the operations of applyOps do. Any other option, as a comment, the constants of an update, the scope of a map-reduce command and the document an operation of applyOps applies are, may hold any document, and none of its keys are kept; nor are those of a $comment. The entries the driver adds for its session, the cluster time and the transaction, which say nothing about the command, are left out.

      An array is recorded with each of its different elements once: an element recorded as one before it in the array is left out, so that the documents of a batch and the values of an $in are recorded the same whatever their number, one or many, and a command is counted as the one statement it is: {"$in": [?]}. An empty array is recorded as [].

      A command is recorded as its name, the database and collection it runs against, and the document of its remaining entries: find shop.book {"filter": {"title": ?}, "limit": ?}. The collection is taken only from a command that runs against one; the first value of any other command is an argument, such as a user name, and is recorded as a value: dropUser admin {"dropUser": ?}.
