[Java] Class CountFinder

    • org.grails.datastore.gorm.finders.CountFinder
    • All Implemented Interfaces and Traits:
      FinderMethod, QueryBuildingFinder
      public class CountFinder
extends java.lang.Object
implements FinderMethod, QueryBuildingFinder

      Implements countBy*. Kept as its own dedicated class rather than a variant of SingleResultFinder: its buildQuery does not reuse DynamicFinder.getJunction at all - for the Or operator it extends the query's own top-level junction directly via Query.disjunction()/Query.add(Junction, Criterion), rather than building a standalone Disjunction added as one nested criterion the way every other finder's shared buildQuery does. This divergence is preserved exactly as it existed before this class existed, not unified with the shared grammar's junction-building.

          Applies this finder's independent (non-DynamicFinder.getJunction) And/Or criteria handling and the count() projection to an already-created query. Exposed as a public static helper so other query-building strategies (e.g. grails-datamapping-rx's count finder, which builds its query outside a Session) can reuse this logic rather than duplicating it.
