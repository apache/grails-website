Package: org.apache.grails.data.mongodb.core.querytail

[Groovy] Class QueryTailCommandListener

    • org.apache.grails.data.mongodb.core.querytail.QueryTailCommandListener
    • All Implemented Interfaces and Traits:
      CommandListener, java.io.Closeable
      @groovy.transform.CompileStatic
class QueryTailCommandListener
extends java.lang.Object
implements CommandListener, java.io.Closeable

      The command listener GORM registers on the client of a MongoDB connection source when query-tail capture is enabled. It records every command the driver is about to send to the QueryTailCapture of the application, without its values, as MongoCommandRedactor takes them out; the command itself is not changed. The driver calls it on the thread that issues the command, so a command is attributed to the request that thread serves.

      The connection source owns the capture, which closes when the connection source closes, so a client stopped for a checkpoint and built again after the restore records to the same capture, whose file is closed for the checkpoint and opened again after it, as every capture file is. The listener is registered as the client's settings are built, but opens the capture only once the datastore the connection source belongs to binds its mapping to it, or the client sends its first command, whichever comes first: a connection source that is built and closed before either, as one built only for its client is, leaves the capture file as it found it. The mapping lets the keys of a command be told to be field names; until it is bound, and in a collection no entity is stored in, only the keys at the top of a condition, a pipeline, a sort or a projection are kept.

      Nothing of this is installed unless QueryTailSettings.SETTING_ENABLED is set, so an application that does not capture pays nothing per command.
