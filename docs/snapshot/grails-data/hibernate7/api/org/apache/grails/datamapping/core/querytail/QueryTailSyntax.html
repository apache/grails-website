Package: org.apache.grails.datamapping.core.querytail

[Groovy] Interface QueryTailSyntax

  • @groovy.transform.CompileStatic
interface QueryTailSyntax

    The lexical syntax of a database, as far as finding the values and the comments of a statement goes: where a string, a number, a quoted name or a comment that starts at a given index ends. QueryTailRedactor scans a statement by asking its syntax about each index in turn, so the rules of a database live in its syntax alone.

    Every SQL database shares the rules of standard SQL: a single-quoted string in which the quote is written twice, a double-quoted name, a -- comment to the end of the line and a {@code /* ... *}/ comment that does not nest. A syntax adds the rules of its database, as verified against the database; the syntax of Cypher, which is not SQL, has rules of its own. Where a rule depends on a server setting the redactor cannot see, such as whether a backslash escapes in MySQL and PostgreSQL, the syntax offers one reading per value of the setting, and a statement is recorded only when every reading finds the same values.

      • public static final QueryTailSyntax CYPHER

        Cypher, the query language of Neo4j: single and double quotes delimit a string, in which a backslash escapes the character after it and a quote written twice is two strings, backticks delimit a name, in which a backtick is written twice, {@code //} starts a line comment and -- does not, block comments do not nest, and a dollar starts a parameter. Whether a line comment ends at a carriage return is read both ways, as Neo4j 5 ends it there and Neo4j 3.5 does not. Neo4j 5 decodes a \u escape that no backslash escapes before it parses, wherever it is written, so a statement with an escape that decodes into a quote, a backtick, a backslash, a line break, an asterisk or a slash, which may end a string, a comment or a name elsewhere, is withheld, and so is one with a backslash outside a string, a comment or a name, which may decode into a value.

      • java.util.List<QueryTailSyntax> readings(java.lang.String sql)

        The readings a statement has under this syntax: one for each value of every server setting the redactor cannot see that changes where a value or a comment of the statement ends. A syntax whose rules the statement does not depend on is its own only reading. A statement that a version of the database reads in a way no reading follows has none, and is withheld.

        Parameters:
        sql - the statement
        Returns:
        the syntaxes the statement is read under, or an empty list when it has no reading

      • boolean takesBareValues(java.lang.String redacted)

        Whether the database may take a bare word of the statement for a value, as SQL Server takes the arguments of a procedure: a word no syntax can tell from a name, so the statement is withheld. A syntax whose database takes no value that way finds none.

        Parameters:
        redacted - the statement as this syntax redacted it: its comments spaces, its values placeholders, and its names, quoted or not, as they are written
        Returns:
        whether the statement takes a value from a bare word
