Package: org.apache.grails.datamapping.core.querytail

[Groovy] Class QueryTailRedactor

    • org.apache.grails.datamapping.core.querytail.QueryTailRedactor 
    • @groovy.transform.CompileStatic
final class QueryTailRedactor
extends java.lang.Object

      Takes the values out of a statement before it is captured. Every string, number and other literal becomes PLACEHOLDER and every comment is dropped, so that a value written into the SQL text, a password in a native query or a key in a comment, never reaches the capture file. Only the recorded copy is redacted: the statement the database runs is not changed.

      Where a value or a comment ends is a question for the QueryTailSyntax of the database the statement runs on, and the redactor asks it about each index of the statement in turn. A statement is redacted under every reading the syntax offers, and is recorded only when all of them give the same text, whitespace aside: a reading that takes a carriage return for the end of a comment and one that takes it for whitespace agree. When they do not, when the statement has no reading, or when a literal, a quoted name or a comment never ends or ends where the syntax cannot tell, the statement is withheld: WITHHELD is recorded in its place, never the statement.

      A value is not always a literal. A statement in which a reading finds that its database may take a bare word for one, as SQL Server takes the arguments of a procedure, is withheld. Nor is a password always a literal: Oracle takes the one IDENTIFIED BY gives as a name, quoted or bare, SAP HANA takes the PASSWORD of a user as one, and a CONNECT may give one bare too, so a statement that gives a password, whatever its database, is withheld whole: one with IDENTIFIED BY, one that creates or alters a user, a role or a login and gives it a PASSWORD, or a PASSWD as Sybase spells it, wherever in the statement it does, as a block or a procedure may, and one that connects, other than by the CONNECT BY of a hierarchical query. Nor is the value of a setting a literal: PostgreSQL, MySQL, Oracle, Db2 and SQL Server, among others, take the value a statement gives a setting as a bare word, so a statement that sets one is withheld whole: a SET that opens the statement, follows a semicolon or opens a block, an ALTER of the system, the session, a database, a role, a user, a login or a routine that sets one, and a function or a procedure created with one.
