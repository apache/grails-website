Package: org.grails.datastore.mapping.mongo.connections

[Java] Class RestartableMongoClient

    • org.grails.datastore.mapping.mongo.connections.RestartableMongoClient
    • All Implemented Interfaces and Traits:
      MongoClient
      public final class RestartableMongoClient
extends java.lang.Object
implements MongoClient

      The MongoClient GORM creates for a connection. It is a stable handle on a driver client that it builds only when it is needed, and that it can close and build again without the handle itself changing.

      The driver connects as soon as a client exists: creating one starts the monitors that open sockets to every server it was given. So this builds its driver client the first time it is used, or when start() asks for it, and not before. A datastore built while an application context refreshes therefore holds no socket until its lifecycle starts it, which is what lets the process be checkpointed with CRaC as the context refreshes (spring.context.checkpoint=onRefresh).

      stop() closes the driver client, which releases every socket it held, and the handle refuses to be used until start() builds a new one. Whatever holds the handle - the mongo bean, a service it was injected into, a Spring Data MongoDatabaseFactory - goes on working after a checkpoint and restore without being told anything. A MongoDatabase, ClientSession or other object obtained from the handle belongs to the driver client it came from, so it is closed with it.

      close() is final: the driver client is closed and the handle cannot be started again.
