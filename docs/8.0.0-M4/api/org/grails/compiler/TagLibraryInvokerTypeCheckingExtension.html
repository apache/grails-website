Package: org.grails.compiler

[Groovy] Class TagLibraryInvokerTypeCheckingExtension

          • org.grails.compiler.TagLibraryInvokerTypeCheckingExtension 
          • class TagLibraryInvokerTypeCheckingExtension
extends org.codehaus.groovy.transform.stc.GroovyTypeCheckingExtensionSupport$TypeCheckingDSL

            A type-checking extension that allows @GrailsCompileStatic controllers and tag libraries to invoke tag library methods without compile-time errors.

            Tag calls in controllers and tag libraries are dispatched at runtime through TagLibraryInvoker#methodMissing and TagLibraryInvoker#propertyMissing. These hooks are invisible to the static type checker, so this extension marks the affected expressions as dynamic, silencing the false-positive errors while preserving full type checking for all other code in the class.

            Detection is by name suffix: a class is treated as tag-dispatching when its qualified name ends with "Controller" or "TagLib" (both carry the TagLibraryInvoker trait at runtime). Note that inner classes whose simple name ends with one of those suffixes will also receive this silencing treatment.

            Two calling patterns are supported:

            • Direct calls on this: link(controller: 'home'), message(code: 'key')
            • Namespaced calls via a namespace dispatcher property: g.message(code: 'key'), my.customTag(attr: 'val')

            Limitation — tag-as-property: Accessing a tag as a property (e.g., def t = link) compiles without error because the unresolved property is silenced, but will throw MissingPropertyException at runtime. TagLibraryInvoker#propertyMissing only returns a NamespacedTagDispatcher for namespace names, not for individual tag names. Use the method-call form (link(...)) instead.

            Scope note: Unresolved variable references in controllers and tag libraries are made dynamic so that namespace dispatcher calls (e.g., g.message(...)) compile. As a consequence, an undeclared identifier used as a dispatch receiver (e.g., a misspelled service name like svcTypo.list()) will also compile without error. Type-safety for method calls on declared fields and local variables is fully preserved.

            Composition with other extensions: because this is a catch-all handler for unresolved calls in controllers and tag libraries, it must run after any other type-checking extension that resolves DSL-style calls (e.g. a criteria extension). When another extension has already resolved a call — flagged on the node via StaticTypesMarker.DYNAMIC_RESOLUTION — this extension defers and leaves the call unhandled, rather than contributing a second candidate method node (which would make the call ambiguous). For this to work it is registered last in GrailsCompileStatic.
